# Заявки с сайта → Telegram: как достроить релей

Затык был такой: тариф Host-A на Reg.ru даёт лимит «1 сайт», и новый сайт под
api.sd-kt.ru создать нельзя. **Решение: новый сайт и не нужен** — api.sd-kt.ru
добавляется как **псевдоним (алиас)** к уже существующему сайту, алиасы лимит
не тратят. Ниже основной вариант (Reg.ru) и запасной (Cloudflare).

Схема в обоих вариантах двойная и надёжная:
- письмо на m2@sd-kt.ru через formsubmit.co работает как раньше (ничего не ломаем);
- параллельно копия заявки мгновенно прилетает в Telegram-группу
  «Syndicat Заявки с сайта» через бота @syndicatru_bot.

---

## Вариант А (основной): PHP-релей на Reg.ru через алиас

Файлы: `send.php`, `.htaccess`, `tg_config.example.php` из этой папки.

### 1. DNS: направить api.sd-kt.ru на хостинг

В панели Reg.ru, в DNS-зоне домена sd-kt.ru добавить запись:

- Тип **A**, имя **api**, значение **37.140.192.35** (IP хостинга Host-A).

Обновление DNS — от 15 минут до пары часов.

### 2. ISPmanager: добавить алиас

Панель: server220.hosting.reg.ru:1500, аккаунт u3359466.

1. **Сайты (WWW-домены)** → выбрать существующий сайт → **Изменить**.
2. В поле **«Псевдонимы» (Aliases)** дописать `api.sd-kt.ru` → Ок.
   Это НЕ создаёт новый сайт, лимит тарифа не тратится.

### 3. SSL-сертификат

В ISPmanager: **SSL-сертификаты** → выпустить/перевыпустить **Let's Encrypt**
на сайт так, чтобы в сертификат попали и псевдонимы (галочка «включить
псевдонимы»/перечислить api.sd-kt.ru). DNS из шага 1 к этому моменту должен
уже работать, иначе выпуск не пройдёт — тогда просто повторить позже.

### 4. Залить файлы релея

Через файловый менеджер ISPmanager в корне сайта (www/<имя сайта>/) создать
папку `tg/` и положить туда:

- `send.php` — как есть;
- `.htaccess` — как есть;
- `tg_config.php` — создать по образцу `tg_config.example.php` и вписать:
  - `TG_TOKEN` — токен @syndicatru_bot (в @BotFather: `/mybots` → бот → API Token);
  - `TG_CHAT_ID` — id группы. Ранее определяли как `-5394858081`; проверить можно так:
    отправить сообщение в группу и открыть
    `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — найти `"chat":{"id":-...}`.
    Если ответ пустой — снять вебхук: `.../bot<ТОКЕН>/deleteWebhook` и повторить.

`tg_config.php` живёт ТОЛЬКО на сервере, в git его не класть.

### 5. Проверка

1. Открыть в браузере `https://api.sd-kt.ru/tg/send.php` — должно показать
   `SYNDICAT relay: OK` (значит алиас, SSL и PHP работают).
2. Тест отправки:

```bash
curl -X POST "https://api.sd-kt.ru/tg/send.php" -d "Имя=Тест" -d "Контакт=+7 900 000-00-00" -d "Запрос=проверка релея"
```

В группе должно появиться «🔔 Заявка с сайта sd-kt.ru». Если ответ `{"ok":false}` —
скорее всего хостинг не выпускает наружу к api.telegram.org: написать в поддержку
Reg.ru (просьба открыть исходящие HTTPS-запросы к api.telegram.org) или перейти
на Вариант Б.

### 6. Подключить сайт

Адрес релея: `https://api.sd-kt.ru/tg/send.php`. Прислать его мне — я впишу в
константу `RELAY_URL` в `index.html` и `catalog.html` (заготовка уже там) и запушу.

## Вариант Б (запасной): Cloudflare Worker

Минус: адрес `*.workers.dev` у части посетителей из РФ может открываться плохо
(Cloudflare периодически ограничивают). Так как релей — параллельный канал, а
письмо через formsubmit всё равно уходит, вариант рабочий, но А надёжнее для РФ.

1. Аккаунт: https://dash.cloudflare.com/sign-up (бесплатно, карта не нужна).
2. **Workers & Pages → Create → Create Worker**, имя `syndicat-relay` → Deploy.
3. **Edit code** → вставить содержимое `worker.js` из этой папки → Deploy.
4. **Settings → Variables and Secrets**: добавить секреты `BOT_TOKEN` и `CHAT_ID`
   (как узнать chat_id — см. шаг 4 варианта А).
5. Проверить тем же curl-тестом на адрес `https://syndicat-relay.<логин>.workers.dev`.
6. Прислать адрес мне — впишу в `RELAY_URL`.

---

## Примечания

- formsubmit.co остаётся резервным каналом в любом случае: если релей упал,
  письмо на почту всё равно придёт.
- Токен бота нигде в репозиторий не попадает: на Reg.ru он в `tg_config.php`
  (закрыт `.htaccess`), в Cloudflare — в секретах воркера.
